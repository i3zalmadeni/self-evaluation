# نظام التقويم الذاتي الذكي – متوسطة لبيد بن ربيعة

نظام مستقل بمستودع مستقل، **مرتبط بالنواة الرقمية مباشرة** ويعمل بقواعدها. الواجهة ثابتة على GitHub Pages، والخلفية قاعدة النواة نفسها (Supabase `labeedsch_PC`).

## الحالة (الهيكل)
- [x] الدخول بحساب النواة (Supabase Auth نفسه) والتحقق من ربط الحساب بسجل منسوب.
- [x] الصلاحيات من أدوار النواة: مدير النواة، منسق التقويم، عضو الفريق، أو صلاحية `self_evaluation:view`.
- [x] صفحات: الرئيسية (تقدم الدورة والمجالات ومستويات الأداء) والمؤشرات الـ52 للقراءة، ودورات التقويم للقراءة والإدارة.
- [x] الواجهة بهوية النواة نفسها (`core.css`).
- [x] إدارة الدورات (إنشاء وتعديل وحالة ونشر) للمنسق ومدير النواة، والدورة مرتبطة بالعام الدراسي في النواة.
- [x] النظام في سجل النواة بحالة `connected`.
- [ ] باقي الوحدات: انظر `docs/roadmap.md`.

## البنية
| المسار | المحتوى |
|---|---|
| `site/` | الواجهة المنشورة (login، dashboard، cycles، indicators) |
| `docs/` | architecture، core-integration، schema، roadmap |
| `supabase/migrations/` | سجل ترحيلات `se_` (القاعدة هي المرجع) |
| `legacy/` | الواجهة والترحيلات القديمة (مشروع Supabase سابق) للرجوع عند نقل الوحدات |

الفرع `backup/pre-core-rebuild-20261111` يحفظ المستودع كما كان قبل إعادة البناء.

## قواعد لا تُخالف
1. الهوية والمنسوبون والأدوار من النواة؛ لا حسابات ولا جداول منسوبين محلية.
2. النظام يقرأ سجلات النواة ولا يكتب فيها، ويكتب في جداول `se_` فقط.
3. المنسق يُعيَّن من النواة (دور `coordinator` لنظام `self_evaluation`)، وأعضاء الفريق يُختارون من منسوبي النواة داخل النظام.
4. قائد المدرسة بمستوى المنسق (قاعدة مقرَّة لكل الأنظمة).
5. الحماية في قاعدة البيانات (RLS)، والواجهة لا تُعتمد للأمان. «لم يُقيَّم» ليس صفراً.
